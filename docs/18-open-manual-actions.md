## 1. Create the backend on Render (blocks the entire demo)

**Why:** the frontend is live at https://phishlens-gules.vercel.app, but there is no backend to call. Sign-in works,
every analysis request fails. About 10 minutes of work and no card.

**Hugging Face is no longer an option.** Custom Docker Spaces require a paid plan, and free ZeroGPU Spaces require an
account at least 30 days old; this account got HTTP 402 for both. Render's free web service runs the same Dockerfile
with no card.

**Steps**

1. Create a free account at render.com (GitHub sign-in is quickest). The Hobby workspace needs no card.
2. **New -> Blueprint**, pick the GitHub repository `yashwanth-creator02/phishlens`, branch `main`, and grant the
   Render GitHub App access to it if asked. Render reads `render.yaml` and shows one service, `phishlens-api`.
3. It prompts for `PHISHLENS_DATABASE_URL`, the only variable Render does not fill in. Value: Supabase dashboard ->
   **Connect -> Session pooler** for project `vmbtdrmevlovvvfvtqmd`, with your database password filled in. If the
   password is unknown, use **Project Settings -> Database -> Reset database password** first. Paste the URI as the
   dashboard shows it (`postgresql://...`); the backend rewrites the driver.
   Keep this value out of chat. `PHISHLENS_WEBHOOK_SECRET` and `PHISHLENS_ADMIN_TOKEN` are generated by Render.
4. Apply. The first build takes roughly 5-10 minutes (ML wheels plus synthetic demo-model training).
5. Open the service URL Render shows and load `/api/health`.

**Done when:** `https://<service-url>/api/health` returns JSON with `"model_loaded": true`. Send the agent that URL;
it then sets `VITE_API_BASE_URL` on the Vercel project, redeploys, and proves an upload-scored round trip.

**Do not** send real personal email to the public service; the bundled model is a synthetic demo. The free instance
sleeps after 15 idle minutes, so open the URL once before a viva to absorb the ~1 minute wake-up.

## 2. Supabase Auth settings (5 minutes)

**Why:** the deployed app can render the sign-in form but email confirmation is on by default, so every new signup
depends on a confirmation mail from Supabase's rate-limited built-in SMTP.

**Steps**, in project `vmbtdrmevlovvvfvtqmd` -> **Authentication**:

- **URL Configuration**: Site URL `https://phishlens-gules.vercel.app`; add the same host under Redirect URLs.
- **Sign In / Providers -> Email**: turn **Confirm email** off for the demo (leave it on if you intend to use a real
  SMTP provider).

**Done when:** signing up on the deployed URL lands you inside the app without a mail step.

## 3. Optional: let pushes deploy the frontend (2 minutes)

**Why:** today the site updates only when the agent runs `vercel deploy --prod --yes`; the Vercel GitHub App has no
access to the private repo.

**Steps:** install the Vercel GitHub App on `yashwanth-creator02/phishlens` (Vercel dashboard -> **Add New -> Project**
shows the install link, or GitHub -> Settings -> GitHub Apps). Then tell the agent.

**Done when:** a push to `main` produces a Vercel deployment on its own (the agent runs `vercel git connect` to finish
the link).

## 4. Fallback if Render refuses you

If Render asks for a card or blocks the account, say so and the agent will instead expose the local backend through a
cloudflared quick tunnel for the demo. Trade-off: the URL changes on every restart, exists only while your machine and
the tunnel are running, and the Vercel build has to be redeployed each time it changes.
